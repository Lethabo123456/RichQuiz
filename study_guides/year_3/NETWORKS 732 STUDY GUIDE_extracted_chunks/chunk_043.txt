How to Respond to Change-Related Problems 
 
If a network issue is suspected to result from a recent change, you have two main options: 
 
• Correct the problem caused by the change. 
• Reverse the change and restore the system to its previous state. 
 
Each approach has risks. Restoring the old conﬁguration is often less risky and faster, 
especially if the change is complex or poorly documented. However, if the problem is minor 
and clearly identiﬁable, it may be quicker and more eﬃcient to correct it directly. 
Tip: If reverting is impossible (e.g., lost data or irreversible hardware damage), solving the 
problem is your only option.

Plan Before Making Changes 
 
Before implementing any network change: 
 
• Develop a contingency plan to reverse the modiﬁcation if needed. 
• Preserve backups of conﬁgurations or hardware components. 
 
o Example: When replacing a memory module, keep the original nearby in case 
the new module is defective. 
o Example: Save a copy of the conﬁguration directory before updating an 
application or device.
